# 发芽笔记→多套写作方案 工作流

> **适用场景**：用户说「再看看其他发芽笔记，重新拿出多套写作方案，并说明优劣」或类似表述时。
> **定位**：anlects-review 阶段4完成后的写作前决策步骤——在进入 classical-content-writer 标准5步流程之前，先决定「写什么」和「怎么整合」。

---

## 触发信号

- 「看看发芽笔记」「重新拿出写作方案」「多套方案」「说明优劣」
- 用户明确要求对多篇发芽笔记做整合评估
- 用户提供了多颗「种子」需要决定优先开发哪颗

---

## 工作流四步

### 第一步：全量检索发芽笔记

用 Get笔记 API 做多轮语义搜索：
1. 搜索核心主题词（如「朱熹」「论语 写作」「发芽」）
2. 合并去重（按 note_id），按日期倒排
3. 筛选真正包含「种子」内容的笔记（有 🌱 标记或包含分析性内容），排除纯通知/指令记录

### 第二步：完整读取每篇发芽笔记

用 Get笔记 detail API 逐一读取完整内容。重点是：
- 种子段落（🌱 标记处）
- Aha 瞬间
- 核心论点
- 跨学科参照（斯多葛、佛学、量子力学等）
- 金句回响

### 第三步：识别融合可能性

在读取全部笔记后，寻找可以「拧成一股绳」的组合线索：
- **主题共性**：多篇笔记是否围绕同一核心概念？（如「无担保」「体系借用」「解释权」）
- **互文增强**：A 笔记的论据能否支撑 B 笔记的论点？
- **层级递进**：是否存在从具体训诂→注疏史→哲学框架的递进关系？

### 第四步：输出多套方案

每套方案必须包含以下字段：

```
### 方案N：标题（一句话核心论点）

**融合笔记**：列出哪些发芽笔记参与融合
**核心论点**：一句话说清文章要论证什么
**结构**：5-7个段落的简要提纲
**优**：至少2条优势
**劣**：至少2条劣势（必须诚实，不可回避）
**适合读者**：一句话描述目标受众
```

## 方案评估维度

最终产出须包含一个比较表：

| 维度 | 方案一 | 方案二 | 方案三 | ... |
|------|--------|--------|--------|-----|
| 原创性 | ★★★★★ | ★★★★ | ★★★ | ... |
| 可读性 | ★★★ | ★★★★ | ★★★★ | ... |
| 学术严谨 | ★★★★★ | ★★★★ | ★★★ | ... |
| 传播力 | ★★★★ | ★★★★ | ★★★★ | ... |
| 字数可控 | ★★ | ★★★★ | ★★★ | ... |

最后给出推荐顺序及理由（1-2句话）。

---

## 常见方案类型

以下是在《论语》发芽笔记中反复出现的方案类型，可作为构思模板：

| 类型 | 特征 | 示例 |
|------|------|------|
| **概念纵向追踪** | 追踪一个概念在注疏史中的演变 | 朱熹的佛学基因（闻思修证→格物致知） |
| **横向跨文明对照** | 东西方哲学概念的平行比较 | 不迁怒 vs 斯多葛 apatheia |
| **主题统摄多章** | 用一条主线串联多章分析 | 孔子不担保的道德（直+不迁怒+不贰过） |
| **注疏权力叙事** | 把注疏分歧读成权力斗争 | 解释权争夺战 |
| **编辑隐结构** | 分析《论语》编纂者的编排意图 | 6.14-6.17 的概念弧线 |

## 关键坑位

1. **不要过早偏向某一方案**：在列出全部方案之前不做推荐
2. **劣势必须诚实**：每个方案至少有2条真实的劣势，不可写成「无明显劣势」
3. **字数预估要保守**：涉及跨学派比较（儒↔佛）的方案天然容易超字数
4. **优先推荐主题统一性高的方案**：多条发芽笔记拧成一股绳 > 单篇笔记独立成文
