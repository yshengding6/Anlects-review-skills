# 跨会话阶段恢复

## 触发场景

当用户要求对某章写文章或继续分析，且本地 `笔记/` 目录下没有完整的 `.md` 阶段文件时，不可直接假设「没有分析过」。前序会话可能已将阶段产物推送到 Get 笔记但未保存本地。

## 恢复流程

1. **先查本地**：`search_files(pattern="{章节号}*", path="笔记/", target="files")` 检查有哪些 `.md` 文件
2. **再查 Get 笔记**：调用 recall API，搜索 `{章节号} {章名}` + `{章节号} 阶段`，top_k=5-10。同时搜索 `{章节号} 阶段1/2/3/4` 逐一确认每个阶段的完整性
3. **制作缺口表**：
   ```
   阶段1: ✅/❌
   阶段2: ✅/❌
   阶段3: ✅/❌
   阶段4: ✅/❌
   ```
4. **询问用户**：用 clarify 呈现缺口表，选项：(a) 先补缺再写作，(b) 跳过缺口直接写作，(c) 先检索完整内容确认够不够
5. **用户选择补缺**：从 Get 笔记召回内容作为参考，从缺失阶段开始正常推进
6. **补完后再补本地**：缺失阶段补完后，同步保存所有阶段到本地 `.md`，确保下次不再触发同样的恢复流程

## 案例

6.17 生直章：本地无 `.md` 文件，Get 笔记有阶段1/3/4，缺阶段2。用户选择先补阶段2再写作。
