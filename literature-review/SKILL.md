# Anlects Review v6.11.0 — 《论语》章句深度分析器

> **适用范围**：《论语》章句分析。四把手术刀中的政治史探针（三桓/季氏/僭越/出仕）、辞仕深探、年代校验等均为《论语》场景特化。**不适用于《易经》《道德经》《庄子》等非《论语》古典文本**——这些文本没有注疏政治史维度，方法论触发条件不成立。
>
> **当用户想研究非《论语》古典文本时**（如《易经》乾卦、《道德经》某章）：不要加载本 skill。改用通用路径：加载 `web-research` skill → 百度百科/搜索搜集材料 → 编译结构化材料汇编 → 展示核心学术争议与可选切入角度 → 等用户选方向后进入深度分析。详见 `references/non-analects-research-workflow.md`。
>
> **适用场景**: 《论语》章句专栏 · 学术史重构
> **核心目标**: 通过硬核方法论重建某一章句的学术史结构，呈现争议焦点、政治动机、解释路径与冷知识命题
> **协作Skill**: `classical-content-writer`（完整写作协议）/ `cultural-comparator`（中西文化比较）

## 核心原则

### 原则零：自适应路径 + 执行确定性

**【强制】方法论路径由文本特征触发，执行过程必须确定。**

**路径选择规则（条件触发）：**

| 文本特征（满足任一） | 必须启用 |
|---------------------|---------|
| 涉及三桓、季氏、公室、君臣、礼制、僭越、权臣、去国、流亡等 | 🔪 政治史探针 |
| 有异文、脱文、衍文、错简、版本差异，或多角度解读 | 🔍 异常检测 |
| 原文概念存在"换近义词后语义是否崩塌"的空间 | 🔄 变量替换实验 |
| 用户提供了注疏原文 | 🔪 六维解剖 |
| 以上均不满足 | 仅基础字词校释 |

**⚠️ 跨章引用核验铁律**：当分析中引用其他章节做编排论证或文本关联时，必须逐条核验原始出处——不得凭记忆或逻辑推断将某句话归入某章。本章会话在6.15由户章的阶段5篇章句法分析和阶段6圆桌辩论中，将子游「事君数，斯辱矣」（实出自《里仁》4.26）误植为《雍也》6.14。6.14原文是孔子语「不有祝鮀之佞，而有宋朝之美」。此错误导致整个「子游单元」编排分析建立在虚假前提上。此后所有跨章引用必须先查原文再写分析，不确定时模糊处理（如「《论语》某章」），不可写死章名编号。

**⚠️ 纵轴穷举核验铁律（6.17生直章追加）**：阶段4纵轴表中对核心关键词进行全书穷举时，每一条目的篇名和章号必须逐条核验——不可凭记忆填写。6.17纵轴表中「直而无礼则绞」被误标为《述而》，实出《泰伯》8.2。纵轴表的论据力完全建立在「穷举准确」上——一处出处错误会导致全书语义弧的绘制出现偏差。规则：纵轴表中每条出现须先用 search_files(「直」target=content path=论语原文目录) 穷举确认，再填入表格。

**⚠️ 政治史探针边界触发规则**：当原文本身不包含政治标记（三桓/季氏/君臣等），但某家注疏（如唐希根编排分析、程树德按语等）明确将本章嵌入政治框架时，按以下流程处理：

1. **阶段1仍标注「边界触发」**：在触发工具判定表中标记为「⚠️ 边界触发」，简述注疏中的政治主张
2. **检查点A询问用户**：是否将政治史探针作为独立模块展开，还是仅在阶段2六维解剖中分析该注疏家的政治立场
3. **用户选择「展开」**：政治史探针按正常流程执行，其产出标注「[基于X注疏的政治框架·非原文自含]」
4. **用户选择「仅解剖」**：政治史探针不独立展开，该注疏家的政治立场作为其六维解剖第4维（立场假设）的一部分处理
5. **默认（用户未明确选择时）**：仅解剖，不独立展开——因为触发规则的基准是原文文本特征，注疏中的政治关联不等于原文有政治内容

**⚠️ 注疏过度解读检测**：当某家注疏将不具政治标记的一般性命题嵌入重型意识形态框架（公羊三世、心性工夫、帝王治道等）时，须逐跳拆解推理链，区分「孔子本意」「合理引申」「学派投射」「强制映射」四个级别。详见 `references/detecting-ideological-over-interpretation.md`。

**执行确定性约束（一旦启用，必须执行到底）：**

1. **顺序固定**：字词校释 → 政治史还原 → 六维解剖 → 异常检测 → 变量替换 → 圆桌 → 综述
2. **禁止跳过已选工具**：启用后不得中途说"不明显"而自行跳过
3. **证据锚定**：所有推论必须标注 [实证] / [推论] / [缺失]
4. **输出结构锁定**：启用什么输出什么，未启用标注"本篇不适用"
5. **术语一致性**：同一次分析中同一概念使用同一术语

**输出风格约束（根约束，覆盖所有阶段和模块）：**

> **禁止进行泛化总结或常识性解释，必须输出结构化分析结果。**

1. **禁止"顺滑解释"**：不得说"这段话的意思是……它告诉我们……"等自然语言总结
2. **强制"结构拆解"**：输出必须呈现为可辨识的结构单元（命题/前提/分歧/路径/证据等级）
3. **强制"模型竞争"**：对任何章句的解释，不得只给出"标准答案"——必须构建至少两种相互竞争的解释模型，每种模型说明能解释什么、不能解释什么
4. **禁止价值判断**：不得说"这种解释更合理""这才是正解"，只呈现结构
5. **禁止现代价值观投射**：解释时必须标注是否受到现代观念影响

**冷知识命题触发规则：**
- 异常检测发现"赘词"或"矛盾词"
- 变量替换发现语义塌陷点
- 六维解剖发现注疏间未被讨论的空白
- 不满足时标注"[本篇无冷知识触发点]"，不强行生成

**沉默区分析的写作边界：**
- 分析层：标注"沉默区"（原文未给出原因/未解释/未展开）是有效的文本观察
- 写作层注意：当原文人物给出了完整、清晰的言语回应时，不得将"未说明原因"升格为"此人沉默"并将其作为文章主干叙事。沉默区工具针对"原文缺失了什么"，不是"此人不说话"。如果人物在原文中说了完整的有语义内容的话，文案主干应基于其言语做判断，而非基于其未说的内容做猜测

### 原则一：本注疏优先原则

1. **只分析用户提供的注疏**，不主动引入其他注家
2. 原文提到其他注家时（如"王肃曰"），可顺藤摸瓜简要分析，但以原文本为主线
3. 例外：用户明确要求多注疏比较时才执行平行分析
4. **本质**：一对一的主题分析，用户给什么分析什么

### 原则二：用户确认铁律

**【绝对强制】每个执行阶段完成后必须暂停等待用户确认。**

1. **阶段间硬停**：阶段1→暂停→确认→阶段2，不得连续执行
2. **修改后复确认**：修改后须再次展示，等用户"OK"才推进
3. **不得以效率为由跳过确认**
4. **不确定时宁可多问**

### ⛔ 保存铁律（最高优先级，优先于所有其他规则）

> **此规则因反复违反（6.4骍角章、6.8伯牛章、6.15由户章共三次全阶段缺失）而提升为最高优先级。agent 在收到用户"确认"/"继续推"/"继续"等任何推进信号后，必须先完成保存验证，再输出下一阶段内容。**

**铁律A——确认后不得空喊**：在对话中说"✅ 已保存"或"阶段X已保存"但从未调用 write_file，这是最高级别的违规。agent 在声称任何文件已保存之前，必须在同一个 tool call 批次中完成 write_file → read_file 验证 → 输出验证结果。

**铁律B——推进前必须完成三步**：用户确认后，agent 必须先执行以下三步，全部成功后才能展示下一阶段内容：
1. write_file 保存本地 .md（含完整内容，不可摘要）
2. read_file 验证文件存在且非空（bytes_written > 0 不够——必须 read_file 读回确认）
3. Get笔记推送（如已配置），间隔 ≥ 2 秒

**铁律C——阶段2多段确认特别规则**：六维解剖被拆分为子批次时（如"继续推X到Y"），每个子批次经用户确认后立即执行铁律B的三步保存。不得积压到全部注疏完成后再统一保存。代理应将每个"继续推"视为等同于"确认"的保存触发信号。

**铁律D——禁止跳过保存直接说"继续"**：agent 不得在未完成铁律B三步的情况下输出下一阶段的任何内容。如果在写下一阶段内容时意识到上一阶段未保存，必须立即中断当前输出、先回补保存。

**违反后果**：用户不得不追问"都保存了吗"——这会中断分析流程并破坏信任。6.15由户章中，agent 在阶段1保存后连续跑完阶段2（4子批次）、阶段3、阶段4、阶段5共6个确认节点全部未执行 write_file，直到阶段5后被用户追问才发现全部缺失。此模式不可再次发生。

**验证方法**：每个"确认"响应中，agent 必须在对话中输出简短的保存确认行（如"💾 阶段2a已保存（本地+Get笔记），继续推6-11号"），作为对自己的约束和给用户的可见保证。

### 原则二付则：确认后自动保存并推进

用户确认某阶段后，**自动执行以下两动作再进入下一阶段**，不再等待"继续"指令：

1. **保存到笔记目录**：将阶段产出保存为 `.md` 文件到该章节的 `笔记/` 子目录，命名格式 `{章节号} {章名简称}_阶段{N}_{阶段标题}.md`
2. **保存到Get笔记**（如已配置）：通过Get笔记API将阶段产出存入云端
3. **自动推进**：保存完成后直接进入下一阶段，无需用户再说"继续"

**用户确认后的自动行为（老丁规则）**：

1. **确认即保存**：用户确认某阶段产出后，立即将当前阶段产物保存到 `笔记/` 目录的 `.md` 文件
2. **确认即推进**：保存完成后，不必再问"是否继续"——直接进入下一阶段
3. **Get笔记同步**：若 Get笔记 已配置，同步保存到 Get笔记；未配置则标注"Get笔记未配置，跳过云端保存"
4. **修改后复确认**：若用户对某阶段产出提出重大修改意见，修改后仍需展示并等确认，确认后同样自动保存+推进

## 方法论：四把手术刀

### 🔪 1. 政治史视角探针

将文本还原为春秋时代的权力博弈，剥离后世道德化滤镜。

- **权力位阶**：识别各方利益主体，分析权力平衡点
- **动机核算**：谁获益？谁受损？是否存在避险策略？
- **礼制工具化**：「礼/德」在维护谁的既得利益？
- **现场还原**：结合人物真实处境，推测言论的「即时指向性」
- **人才制度史（子探针）**：当原文涉及「举贤/选人/用才/出身」时，追踪该章被后世人才选拔制度（察举制→征辟制→九品中正→科举制）反复调用的历史——每一代注疏不只是「解读经典」，更是「用经典为当下制度背书」。详见 `references/talent-selection-framework.md`。
- **颜回生平与不仕（子探针）**：当原文涉及颜回贫困、不仕、乐处等问题时，参考 `references/yanhui-supplementary-sources.md`——含庄子·让王（vs 韩诗外传来源标注陷阱）、上博简《君子为礼》、战国亩产参照。⚠️ 庄子·让王中颜回不仕对话常被误标为韩诗外传，须核查docx原文的引用来源。
- **子夏传记与认知风格**：当原文涉及子夏时（出现于为政2.8、八佾3.8、雍也6.11/6.13、颜渊12.5/12.22、子路13.17、子张19.3-19.13等章），参考 `references/zixia-biography.md`——含完整生平（前507-前400，107岁）、认知风格（"识小"积累型 vs 颜回"闻一知十"）、西河设教与弟子群（跨儒法兵墨四家）、与子游路线之争、晚年丧子失明、与6.11为儒章的深层关联。
- **道与政之辨（子探针）**：当原文涉及弟子在权臣手下任职且孔子对其表达不满时，启用"道与政"结构性冲突框架——弟子是双重代理人（师的道 vs 主的政），"力不足"可能是结构性困境的真实表达而非托词。详见 `references/dao-vs-zheng-framework.md`。
- **冉求跨章证据链（子探针）**：当原文涉及冉求（冉有/冉子）时，参考 `references/ranqiu-cross-chapter-chain.md`——含6.3（继富）→6.10（女画）→3.6（旅泰山）→11.17（鸣鼓攻之）的完整时间线与跨章叙事。冉求四次被批评不是独立事件，而是"道与政夹缝"叙事的四个节点。
- **制度忠诚 vs 心术化（子探针）**：当原文涉及"径""由""道"等空间/路径概念，且注疏传统将之心术化（解释为心术/人品而非制度/法律）时，参考 `references/legal-compliance-vs-moral-consciousness-6.12.md`——"行不由径"首先是法律遵守，朱熹的心术化解读服务于宋代心性哲学议程。

- **辞仕深探（子探针）**：当原文涉及某人「辞仕/拒仕/不仕/退隐」时，**强制**执行以下三步：

  1. **同门仕历对照**：列出同门（或同僚）在同一势力下所仕的职位清单，逐一标注职位性质（家宰/邑宰/中枢/外放等）
  2. **制度位置区分**：用制度性文献（如贾公彦《仪礼疏》等）区分当事人被征召职位与同门所仕职位的制度性差异——权力来源、俸禄来源、武力基础、与权臣的空间距离
  3. **深层原因判定**：若制度位置不同，则"独辞"的原因首先指向制度位置差异（风险不同、回旋余地不同），而非道德优越。道德化解释（"视不义富贵如犬彘"）只有在制度位置相同仍独辞时才可成立

  > ⚠️ **触发陷阱**：当文本出现"某人拒绝X"时，分析者容易直接追问"他为什么拒绝"——但更应该先追问"其他接受了X的人，接受的是同一个X吗？"。如果职位性质不同，"拒绝"和"接受"之间就没有矛盾需要解释。典型案例见 `references/position-type-verification-6.7.md`。

  **三层叠加**：当"制度位置区分"发现差异时，用"制度位置→政治算计→个人判断"三层叠加替代单一原因归因——拒绝单一原因（道德论选"犬彘之禄"、务实论选"难治"、调和论选"可救不可救"都是单因归因的错误）。

- **僭越时间线校验**：当文本涉及「季氏不臣」「三桓僭越」等判断时，不得假设僭越始于当前执政者——必须回溯该家族僭越行为的完整时间线，校验"不臣"是否构成辞仕的充分条件（若同门仕同一家族而不辞，则"不臣"非唯一原因）。

**⚠️ 年代校验前置**：执行政治史探针前，必须先完成阶段1的年代校验。如果年代校验发现「孔子在职」假设与人物年龄矛盾，则：
- 「与之粟」的性质从「公权分配」变为「私人资助」
- 「家宰」的制度含义需要重新界定
- 整个权力位阶分析需要标注「[年代存疑，以下基于X假设]」
- 不得在未校验年代的前提下做出「僭越职权」「公私混淆」等强判断

### 🔪 2. 注疏六维解剖

将历代注疏视为"解释机器"，拆解六维度：

1. **文本解释**：表层理解是什么？
2. **方法论**：训诂、义理、考据、玄学？
3. **概念重构**：是否对原文概念重新定义或挪用？
4. **立场假设**：预设了怎样的政治/哲学立场？
5. **隐含前提**：哪些前提被默认接受但从未声明？
6. **时代动机**：该解释在其历史语境中服务于什么目的？

**⚠️ 六维解剖陷阱：动词忽视**——注疏传统倾向于将分析焦点集中于原文中的名词性概念（"命""礼""仁"等），而系统性地忽视物理动作动词（"执其手""自牖""问之"等）。在解剖注疏时须逐家检查：该注家是否对原文中的物理动作给出了解释？如果多家注疏集体忽略同一个动作动词，这一集体沉默本身就是分析对象。典型案例：伯牛章九家注疏均聚焦"牖"和"命"，无一家将"执其手"作为核心分析对象。

**⚠️ 六维解剖陷阱：编纂者适配**——当解剖对象是「集释者/编纂者」（如程树德《论语集释》）而非「注疏者」时，六维度须做适应性调整：分析对象从编纂者的解释立场切换为编纂者的材料分类方法及其透露的学术立场。详见 `references/six-dimension-adaptation-compilers.md`。

**⚠️ 六维解剖陷阱：康熙日讲 vs 朱熹集注措辞混淆**：康熙《日讲》常以流畅白话转述朱熹观点，措辞极相似但归属不同。六维解剖中对某注家做第1维「文本解释」时，引用「内有忠信诚悫之本然者」「外有威仪文词之灿然者」等展开性措辞须核查原文——此类流畅描述多出自康熙《日讲》而非朱熹《集注》。不可因语感顺手而将日讲转述作为集注原文引用。6.16文质章触发：agent六维解剖中将日讲措辞误标为朱熹，被用户逐条核验纠正。**此陷阱在文章写作阶段同样触发**——文章引用文/质定义时，若写「朱熹说内有忠信诚悫之本然者」，同样是在用日讲顶替集注。规则：凡引用带展开性描述的定义措辞，先查用户提供的docx原文确认归属。

**⚠️ 六维解剖陷阱：注疏引文须原典校验**——当注疏家引用外部文献（《左传》《史记》《韩非子》等）作为论证支撑时，须回溯原典进行三重校验（原文还原→语境还原→论证强度重估）。注疏家的选择性引用本身就是六维解剖中「立场假设」维度的分析对象。详见 `references/original-source-verification.md`。

### 🔪 3. 文本异常检测

扫描"并非必须但被刻意保留"的词汇，寻找逻辑断裂处：

- 标记**赘词**——语法上可省略但被保留的字
- 标记**矛盾词**——同一语境中语义方向不一致的用词
- 标记**沉默区**——逻辑上应当出现但缺席的概念
- **特殊沉默区：被描述者沉默**——当原文中某人被提及但全文无其任何言语记录时，这是特定类型的沉默区（如伯牛章伯牛无一言、乞醯章微生高无一言）。注疏传统常忽略此类沉默，将分析焦点全部置于发言者身上
- 异常点是冷知识命题的高概率来源
- **扩展：现代读者认知错位探测**——当某关键词的现代常用义与原文语境义存在系统性偏差时，此偏差本身就是分析对象。详见 `references/modern-reader-cognitive-mismatch.md`

### 🔪 4. 变量替换实验

对文本执行最小化替换实验，通过"语义塌陷"反证原意图：

- **换动词**：替换核心动词，观察语义是否崩塌
- **换对象**：替换动作对象，观察逻辑是否成立
- **换时间**：前移或后移时间状语，观察政治含义是否改变
- **塌陷判定**：替换后语义重大偏移 → 原词具有不可替代指向性

## 研究流水线（完整七步引擎）

> 本流水线将四把手术刀和提示词库串联为可复用的完整研究引擎。每一步产出的结构化成果是下一步的输入。

```
① 注疏拆解 (Prompt 1)
   → ② 解释竞争 (Prompt 2)
   → ③ 认知反思 (Prompt 3)
   → ④ 模型选择（研究者做）
   → ⑤ 压力测试 (Prompt 4)
   → ⑥ 分歧本质 (Prompt 5，多注疏时）
   → ⑦ 写作准备 → 哲学转译 (Prompt 6) → 文章骨架 (Prompt 7)
```

**流水线使用规则：**

1. **不可跳步**：①→②→③→⑤→⑦ 是强制顺序。④ 是研究者的人工判断节点。⑥ 仅多注疏比较时插入。
2. **每步产出结构化**：每步必须输出指定结构化格式（见提示词库各 Prompt 的输出要求），不得输出"讨论""分析"等自由文本
3. **不得提前合成**：在流水线跑完⑤之前，不得做"综合判断"或"最终解释"
4. **输出风格约束持续生效**：流水线全程遵守原则零中的输出风格约束

**与交互式工作流的关系：**
- 流水线是"微观引擎"——在交互式工作流的每个阶段内部运行
- 阶段1（原子化扫描）内部可运行 ①
- 阶段2（深度挖掘）内部可运行 ②③④⑤⑥
- 阶段5（多格式生成）内部可运行 ⑦
- 交互式工作流的检查点（A/B0/B）仍然保留，用于研究者确认

## 交互式工作流

### 批量章节分析模式

当用户要求对多篇章句进行批量分析（如"全量分析，每章都做到阶段4"）时：

1. **先盘点**：列出所有待分析章节，标注哪些已有阶段4、哪些缺、哪些无注疏材料
2. **确认范围**：用 clarify 让用户选择——补缺/全量重做/含搜集材料
3. **逐章串行**：每章完成阶段1-4后再进入下一章，不跨章并行（六维解剖等长内容需保持上下文连贯）
4. **阶段间自动保存+推进**：批量模式下更不可中断——每阶段确认后立即保存（本地.md + Get笔记），然后自动推进，无需用户再说"继续"
5. **进度追踪**：用 todo 工具跟踪每章状态（pending → in_progress → completed）

### 触发规则

| 用户信号 | 行为 |
|---------|------|
| 「从头重做」/「重新分析」 | 丢弃同目录下所有已有分析产物（article-layout.html、infographic/*.png、旧docx），从阶段1开始完整重跑。不参考旧分析，不复制旧结论。 |
| 「继续」/ 指定会话ID | 读取已有阶段文件，从上次中断处继续 |
| 「确认，并先保存」 | 保存当前阶段产物到 `笔记/` 目录的 `.md` 文件，再进入下一阶段 |
| 「全量分析」「每章都做到阶段N」 | 批量分析模式（见下方） |

### 批量分析模式

当用户要求对多篇章句执行同一阶段深度（如「全量分析，每章都做到阶段4」）时，执行以下流程：

1. **盘点阶段**：扫描 `笔记/` 目录，列出每章的注疏汇编docx和已有阶段文件，生成完成状态表
   - 格式：`章节号 | 有注疏汇编 | 阶段1 | 阶段2 | 阶段3 | 阶段4`
   - 向用户展示并确认范围（哪些章需要补齐、哪些已有可保留、是否需要从头重做）
2. **按章串行执行**：对每章按阶段1→2→3→4顺序推进，每章内部的确认/保存规则不变
3. **章间衔接**：一章阶段4确认保存后，自动开始下一章的阶段1，无需用户额外指令
4. **进度追踪**：用 todo 工具维护待分析章节列表，每完成一章标记 completed
5. **无注疏汇编的章**：在完成状态表中标注「缺材料」，不强行分析——提示用户需要先搜集注疏

**⚠️ 批量模式下的确认规则**：每章内部的检查点（A/B0/B）仍需用户确认，但章与章之间自动衔接——用户说一次「全量分析」就够了，不需要每章开始前再确认。

### 前置：Get笔记发芽笔记检索 + 跨会话阶段恢复

**如果用户已配置Get笔记，在阶段1开始前先搜索该章的发芽笔记。** 发芽笔记是用户之前对该章的思考碎片或灵感记录，可能包含：未进入正式分析的原始洞察、跨文本联想、现代类比、情感反应等。这些内容是分析的重要补充，不应等到归档阶段才去检索。

检索方式：加载 `getnote` skill → 调用语义搜索接口，搜索 `{篇章名} 发芽` 或直接搜 `{篇章名}` → 将相关结果作为阶段1-4的补充输入。

**⚠️ 跨会话阶段恢复**：同步检查本地 `笔记/` 目录和 Get 笔记中是否已有该章的阶段分析。若阶段仅存在于 Get 笔记而本地缺失，按 `references/cross-session-stage-recovery.md` 流程处理——先向用户呈现缺口表，确认补缺策略后再推进，避免重复分析或遗漏阶段。

### 前置补充：结构化研究大纲法（Deep-Research 方法论注入）

> **来源**：Weizhena/Deep-Research-skills 两阶段研究流程（大纲生成 → 并行搜索 → 汇总报告）
>
> **适用场景**：当用户未预准备注疏 docx、需从零搜集材料、或章句涉及非《论语》领域（制度史、考古学、出土文献）需跨领域搜索时，在执行阶段1之前先运行结构化研究大纲法。完整流程见 `references/structured-research-outline-method.md`。

**两阶段流程**：

1. **Phase 1：生成研究大纲** — 将研究目标拆解为 items（独立搜索条目）+ fields（每个条目的搜索维度）。大纲必须暂停等待用户确认——用户可增删 items、调整 fields、指定优先级。
2. **Phase 2：深度搜索** — 按 item 逐一搜索（串行），每个 item 的 fields 可并行搜集。搜索源优先级：百度百科 → 古诗文网 → 学术数据库 → 通用搜索。每个 item 输出 [实证]/[推论]/[缺失] 证据分级。
3. **Phase 3（可选）：生成研究报告** — 汇总为结构化报告，含交叉收敛线（不同 items 之间的印证/矛盾）和盲区清单（现有材料无法回答的问题）。

**与阶段衔接**：结构化大纲法产出的研究报告直接作为阶段1的补充输入——特别是年代校验的外部生平检索、制度性文献定位，都从研究报告中提取。

**禁止行为**：不要用结构化大纲法替代注疏分析（它是前置步骤，不替代六维解剖）；不要在大纲确认前就开始搜索；不要在用户明确表示「不需要额外搜索」时强制执行。

### 阶段间保存规则

每个阶段完成并经用户确认后，**自动执行以下保存动作**，无需等待用户再次指令：

1. 保存为 `笔记/` 目录下的独立 `.md` 文件
2. 若 Get笔记 已配置 API，同步保存到 Get笔记（标签：`论语研究`+阶段标签）
3. 保存完成后直接进入下一阶段——**不再问「是否继续」**

```
06雍也篇/笔记/
├── 6.4 骍角章_阶段1_原子化扫描.md
├── 6.4 骍角章_阶段2_深度挖掘与政治还原.md
├── 6.4 骍角章_阶段3_动态圆桌.md
├── 6.4 骍角章_阶段4_证据分级综述.md
└── ...
```

文件命名：`{章节号} {章名简称}_阶段{N}_{阶段标题}.md`。每个文件独立可读，包含该阶段的完整输出。阶段2含材料遍历清单+六维解剖时可合并为一个文件。

**⚠️ 文件完整性陷阱（.md + Get笔记双重）**：保存到 `.md` **和**推送至 Get笔记 时，都必须写入该阶段的**完整内容**——不可写入摘要、索引或指向对话的占位符（如"完整内容见上轮对话输出，此文件为索引存档"）。每个 `.md` 文件和每条 Get笔记 必须独立可读，不依赖对话上下文即可理解完整分析。

**此陷阱在以下场景反复触发（重复犯错模式）**：
- 六维解剖内容特别长时，agent 会将对话中的详细输出（表格+逐家六维度分析）压缩为简短摘要再写入文件。**规则：对话中输出了什么，文件里就写什么。不因为"文件太长"而自行精简。**
- Get笔记推送时，agent 常将阶段完整内容替换为200-500字摘要。**规则：Get笔记的 `content` 字段 = `.md` 文件的完整正文，不做二次摘要。**

**验证方法**：每个阶段保存后，检查 `.md` 文件大小与对话中该阶段输出的体量是否匹配。六维解剖（19家×6维度）的完整文件通常 6,000-10,000 字符；若保存后文件仅 2,000-3,000 字符，说明已被压缩，须重写。

**⚠️ 保存空喊陷阱（重复犯错模式）**：确认后自动保存时，agent 可能在对话中说「✅ 已保存」但从未实际调用 write_file。此话术本身不构成保存——必须确实调用了 write_file 且返回了 bytes_written > 0。此陷阱在阶段2/3/4的确认环节反复触发（agent 说「已保存到本地 .md + Get笔记」但磁盘上文件不存在）。

**防陷阱措施**：
1. 每次确认后保存时，在同一个 tool call 批次中依次执行：(a) write_file 写本地 .md → (b) 用 search_files 或 read_file 读回校验文件存在且非空 → (c) 推送 Get笔记。三步必须同批次执行，不可分拆为「先说已保存、稍后再补」。
2. 禁止在任何对话框中声称「已保存」除非刚才确实执行了 write_file 调用。如果 write_file 因权限等问题失败，必须如实告知用户而非继续推进。
3. 目录不存在时 write_file 可能静默失败——保存前先确保目录存在（mkdir -p）。

**⚠️ 多段确认陷阱（新增，6.15由户章教训）**：阶段2六维解剖常因内容巨大而被拆分为多个子批次（如 1-5号、6-11号、12-14号、15-18号），每批次经用户确认（「继续推X到Y」）后 **必须立即保存该子批次到本地 .md + Get笔记**，不得积压到全部18家完成后再统一保存。此陷阱在 6.15 由户章触发：agent 在阶段1保存后，连续跑完阶段2（4个子批次）、阶段3、阶段4、阶段5 共6个确认节点，全部未执行实际 write_file，直到阶段5后才被用户追问发现全部缺失。完整失败序列见 `references/save-failure-case-6.15.md`。

**关键信号词扩展**：以下所有用户用语均为保存触发信号——「确认」「继续」「继续推」「OK」「行」「好」「收到」「确认清单，继续」「确认，进入」。代理在看到这些信号时，必须先完成保存验证，再输出下一阶段内容。

**命名规则（拆分阶段）**：当某阶段因内容过大拆分为多个 .md 文件时，命名格式为 `{章节号} {章名简称}_阶段{N}{字母}_{子标题}.md`。如 `6.15 由户章_阶段2a_六维解剖_1-5号.md`、`6.15 由户章_阶段2b_六维解剖_6-11号.md`。每个子文件独立保存、独立推送 Get笔记，且需在文件名中明确标注子范围以便后续检索。

**⚠️ Get笔记API凭证Shell转义陷阱（新增）**：Get笔记 API Key 格式为 `gk_live_xxx.yyy`，含点号等特殊字符。通过命令行参数或环境变量传递时可能触发 shell 转义错误（unexpected EOF）。**正确做法**：将 API Key 直接硬编码在推送脚本文件中（patch写入），然后运行脚本，运行后删除脚本。不要通过 `$KEY` 变量或命令行参数传递。

**⚠️ 已有文件发现陷阱**：当某章的 `笔记/` 目录中已存在先前分析的 `.md` 文件（如阶段1已完成）或用户之前撰写的独立分析docx（如"老丁观点分析"等），必须先读取这些文件并作为后续阶段的输入——不得忽略已有分析、从零重做。批量补缺模式下尤其注意：跳过的阶段应从已有文件中提取上下文，而非假设没有前序信息。

### 阶段 1：原子化扫描（考据层 + 政治史还原）

逐字训诂 → 关键异文 → 底本与校本 → **年代校验** → 运行异常检测 → **【若政治史探针已触发】政治史还原**

> ⚠️ **重要**：当文本涉及三桓、季氏、公室、君臣、权臣、出仕等政治内容时，政治史还原是阶段1的有机组成部分，**不推迟到阶段2**。政治背景决定字词解释方向（如"何有"的语用力取决于孔子是执政者还是流亡者），必须与原子化扫描同时完成，才能形成完整的基础判断。

**【强制】年代校验步骤**（插入于异文与异常检测之间）：

当文本涉及具体历史人物行动时，必须执行以下校验，否则阶段2的政治史还原可能建立在错误前提上：

1. **人物年龄推算**：查《史记·弟子传》等文献中的人物年龄差，推算事件发生时各人实际年龄
2. **年龄-行为校验**：该年龄是否能执行文本所述行为？（如：9岁能否出使齐国？15岁能否担任家宰？）
3. **孔子身份校验**：若涉及孔子分配资源（粟、禄等），确认孔子当时在职还是去职——这直接决定"与之"是公权行为还是私人行为
4. **注疏共识校验**：所有注家是否在同一个未验证的假设上达成了共识？如果都假设"孔子在职"但无人校验人物年龄，则该共识可能是系统性盲点

**5. 外部生平检索**：当docx中人物信息不完整（卒年不详、任职履历不详、家族关系缺载），须搜索百度百科等外部来源交叉核验——不局限于用户提供的docx。关键检索点：生卒年、任职履历、家族成员、同时代人对该人物的记载、后世追封/祭祀记录（可反推生平）。典型案例：伯牛章仅知"少孔子七岁"，通过百度百科补全"孔子司寇时伯牛任中都宰""冉离生三子（伯牛/仲弓/冉求）""后得恶疾"，从而锁定伯牛死于中年48-55岁而非夭折。

**6. 传记时间线交叉验算**：当涉及多个人物关系（兄弟、同僚、师生），须利用已知年龄差推算未知事件的时间窗口。如：伯牛比冉求大约22岁→若伯牛死于48-55岁，冉求此时25-33岁已成年出仕→任何"尚未/还没"的判断须经此验算，不得凭直觉推断。运算方法：用最可靠的生年差作为锚点，推算模糊人物在关键事件点的年龄区间。

**年代校验的典型输出格式**：

| 时间假设 | 人物A年龄 | 人物B年龄 | 行为可行性 | 矛盾 |
|---------|----------|----------|-----------|------|
| 假设1：孔子在职(XXX-XXX BC) | X岁 | X岁 | 可/不可 | 描述 |
| 假设2：孔子去职/返鲁(XXX BC后) | X岁 | X岁 | 可/不可 | 描述 |

**补充信息来源（百度百科）**：当《史记·弟子传》等传统文献无年代记载时，百度百科常包含后世辑佚的履历信息（如伯牛"任中都宰于孔子司寇期间"、"因恶疾早逝"、冉离生三子等）。此类信息应标注出处为"百度百科"并在可靠性列备注"[后世辑佚·出处待核]"，不得混入[实证]级证据。对"少孔子七岁"等传统记载，注意刘宝楠已注"不审何据"——此类信息虽被广泛引用，但原始出处存疑。

**传记时间线交叉验算**：当涉及多个人物（如兄弟、同僚）时，必须推算年龄差，用已知生年锚定未知事件的时间区间。例：伯牛（少孔子7岁）与冉求（少孔子29岁）相差约22岁→若伯牛死于48-55岁，冉求此时25-33岁已成年。任何"尚未/还没"的判断须经此验算。

**制度性文献校验**（年代校验的延伸）：当年代存疑影响"行为性质"判断时，需进一步校验制度性文献：

1. **采地校验**：当事人（如孔子）是否有采地？这决定家臣是邑宰还是家相，进而决定俸禄来源（采地税收 vs 个人俸禄分配）
2. **制度文献定位**：寻找同时代的制度性疏解（如贾公彦《仪礼疏》）中对相关制度的明文区分——这类文献的证据力高于义理推断
3. **俸禄性质判定**：若采地存疑，则"与之粟"的性质标注为[待定]，不得在公权/私权之间做强判断

> ⚠️ **陷阱预警**：传统注疏几乎从不做年龄-行为校验。当所有注家对"孔子身份"达成共识时，务必用年龄算术交叉验证——如果算术推翻共识，这是冷知识命题的强力触发点。
>
> ⚠️ **用户提供材料的异文陷阱**：同一段注疏原文（如刘宝楠「子游/子羽独奉而行之」）在不同来源（唐熙根引述 vs 程树德引述 vs 用户直接提供的《论语正义》原典）中可能存在关键异文。**当用户先后提供同一段注疏的不同版本时**，必须以原典（用户最后提供/直接标注来源的版本）为基准，在解剖中明确指出异文及其两条阐释路径的差异，不可默认较早版本正确。典型案例见 `references/textual-variant-cross-check.md`。
>
> **二次陷阱**：即使年龄校验推翻了"在职"假设，注疏传统仍会自动将场景解读为"行政场景"——因为儒家经典必须服务于治术。需用制度性文献（非义理推断）来校验"俸禄来源"，而非仅靠年龄推算。
> 
> 典型案例见 `references/dating-verification-case-6.3.md` 和 `references/dating-verification-case-6.8-boniu.md`（外部生平检索补全案例）。

⏸️ **检查点 A**：展示基础事实清单（含年代校验结果 + 政治史还原【若触发】），等待用户确认。

### 阶段 2：注疏层深度挖掘（动机层）

> **注**：政治史探针已在阶段1完成（若触发）。阶段2专注注疏分析。

政治史探针 → **互文检索**（单章平行文本 + 如需横向主题比对，见 `references/thematic-cross-comparison.md`） → 经史验证 → 话语权陷阱识别 → **材料遍历清单** → 注疏六维解剖（逐一）

> **替代路径：纵轴注疏谱系法**。当注疏跨越多时代且核心概念有语义漂移时，可用五级纵轴法替代逐家六维解剖，产出更有纵向叙事力的分析。详见 `references/five-tier-commentary-history.md`。
>
> **互补方法：横轴互文链法**。在注疏分析之外，对《论语》全书进行主题链扫描（提取2-3个核心关键词→全书穷举→绘制语义弧→链间交叉）。与纵轴法互补——纵轴看注疏演变，横轴看文本网络。详见 `references/intertextual-chain-analysis.md`。
>
> **互补方法：轴心分歧框架**。当材料中存在一对早期注家的根本性分歧（如马融vs郑玄对同一关键词的行为域/本体域之争），以该分歧为组织轴心，将全部后续注疏按「八扇门」分类（A路线/B路线/升级版/第三条路/反方/综合/官学/现代转译），追溯时间轴上每代注疏对该分歧的操作类型，派生六条子裂痕追踪表。与纵轴法互补——纵轴按时代分层，轴心法按张力关系组织。详见 `references/axial-divergence-framework.md`。

> **⚠️ 材料遍历清单（强制前置步骤）**：在进行六维解剖之前，必须先遍历用户提供的所有材料，列出**每个独立注疏立场/学者**的完整清单。用户提供的 docx/文本中出现的每一位有独立观点的注家都必须出现在清单上——不得遗漏。
>
> 格式示例：
> ```
> 用户提供的注疏材料共包含以下独立立场，将逐一解剖：
> 1. 何晏《集解》（汉魏·训诂）
> 2. 朱熹《集注》（宋·义理）
> 3. 刘宝楠《正义》（清·考据）
> 4. 程树德《集释》（民国·清算）
> 5. ……
> ```
>
> 清单经用户确认后方可开始逐一解剖。解剖顺序建议按时间线排列（从早到晚），以便观察概念链的演变。
>
> **⚠️ 待考注家处理规则**：当材料遍历清单中出现身份不明的注家（如仅标注「王氏笺解」而未标全名、或生卒年代待考）时：
>
> 1. **先尝试快速查证**：加载 `web-research` skill，搜索注家身份。控制在2-3次尝试内，不在网络限制环境中反复重试不同的搜索引擎/方案。
> 2. **若网络查证失败**（GFW环境下常见）：直接基于训练知识给出最佳推定，需提供推定依据（著作体例、引文风格、时间线位置等）并标注「据XX推定为XX，未获网络直接验证」。
> 3. **若有多个候选**：列出候选并给出首选，标注存疑。不可因待考而阻塞整个清单的确认流程。
> 4. **时间线定位**：即使确切生卒年待考，也须给出大致时代归属（如「明末清初」而非「待考（清？）」），以便后续六维解剖按时间线排列。

**⚠️ 追加材料陷阱**：六维解剖进行中，用户可能追加提供新材料（如程树德《集释》中收录的历代注疏）。此时必须：(a) 暂停当前解剖；(b) 将新增独立立场追加到材料遍历清单中；(c) 对新增材料逐一完成六维解剖后，再继续原来的解剖流程。**禁止**将新增材料压缩为「已在某家解剖中提及」而跳过独立解剖——程树德「发明」板块中收录的材料（焦竑、赵佑、真德秀、李颙、宦懋庸等）各自具有独立的学术立场和时代动机，不得因「程树德已引用」而合并处理。

**⚠️ 编纂者处理规则**：当材料遍历清单中包含「编纂者/集释者」（如程树德《论语集释》）时，六维解剖须做适应性调整——分析对象从「编纂者的解释立场」（他没有自己的释义）切换为「编纂者的材料分类方法及其透露的学术立场」。判断不在他对原文的释义中，而在他的材料取舍（板块分类如考异/音读/考证/集解/古注/集注/发明）、排列顺序、以及偶尔插入的按语中。详见 `references/six-dimension-adaptation-compilers.md`。

**用户确认后自动化**（老丁规则）：确认即保存材料遍历清单到本地 .md + Get笔记，然后直接进入逐一六维解剖（无需再等确认）。

> **关键规则**：所有注疏解读必须全部完成后，才能进入阶段3。
> 禁止在单个注疏解读过程中召开圆桌会议。

### 阶段 3：冲突驱动型动态圆桌（论辩层）

**前置条件**：阶段2全部注疏解读完成后方可启动。

**角色点将**：
- 从资料中识别代表学者。**默认目标6位，但可根据材料丰富程度和覆盖需求适当增减（用户可指定"汉代两个、宋代三个……"等按时代分配）**。底线：不少于4位，无上限
- **强制**：至少两组学术立场互为"天敌"
- **固定席位**：苏格拉底（Socrates）作为第N+1位
- **主持人**：默认由agent担任；用户可指定主持人（如李零等学者角色），此时主持人负责开场定调、控场追问、总结决议。主持人选择应与章句气质匹配——情境还原型章句选李零（还原具体情境）、心性哲学型章句选钱穆（温厚通达）、人情伦理型章句选南怀瑾（人情通达），详见 `references/roundtable-host-selection.md`
- **列席**：用户可指定列席者（如老丁），列席者在末位发言，不做硬碰撞但可做独立判断

**议程**：
1. 各学者依次发言，须引用原文进行"硬碰撞"
2. 苏格拉底使用**助产术**进行逻辑清洗
3. 针对论证中的"概念偷换"或"时代错置"，提出**3个致命反问**
4. **重点追问**：**"这个解释是为了掩盖什么政治尴尬？"**

**可选尾声：苏格拉底三刀**。在所有学者发言完成后，苏格拉底做总结性反问——不是针对具体学者，而是针对整个注疏传统的基本假设。三刀分别刺向：

1. **根基概念未定义**：「你们争了两千年，但那个最核心的词——有没有任何一个注家给过定义？」
2. **形而上学不可观察**：「你们用不可观察的东西解释可观察的句子——凭什么？」
3. **孔子可能只是在聊天**：「如果孔子这句话没有体系意图，你们两千年的争论是建立在什么上面？」

三刀不是要「赢」辩论，是要暴露注疏活动本身的未经审查的前提。主持人（或苏格拉底本人）在三刀后做收束总结。详见 `references/socratic-three-knives.md`。

### 阶段 4：横纵分析（输出层）

> **⚠️ 阶段4三轴强制结构**：横纵分析必须覆盖三个维度，缺一不可。不可仅在《论语》内部打转。

**三轴框架（强制）：**

| 轴 | 范围 | 产出 | 说明 |
|----|------|------|------|
| **横轴（篇内）** | 本章在所在篇中的前后章关联 | 章际锁链——概念递进弧线、编辑意图推断 | 如 6.14→6.17 四章构成「行→免→质→直→幸」弧线 |
| **纵轴（全书）** | 核心关键词在《论语》全书中的所有出现 | 语义弧——全书用法穷举、本章的独特位置 | 如「直」全书12+处，仅6.17在存在论/本体论层面 |
| **跨学派横轴** | 孔→孟→荀→佛（及其他学派如道/法） | 概念蜕变链——观察同一概念在后世学派中如何被升级/删改/置换 | 如「幸」从孔子概率论→孟子边缘化→荀子删除→佛学置换为三世因果 |

**跨学派横轴的操作方法**：

1. **锁定关键词**：从本章提取1-2个核心概念（如「直」「幸」），追踪其在孟、荀、佛中的对应概念
2. **制作对照表**：孔子的原始定位 → 孟子的升级/补充 → 荀子的反转/删除 → 佛学的置换/覆盖
3. **追踪「衰退/置换」**：找出被后世学派删掉或置换的关键字（如荀子删「幸」、佛学用三世因果置换「幸」）
4. **绘制汇流图**：用ASCII图展示四条路径的分叉与合流
5. **交叉收敛线**：将三轴发现汇合为2-3条最终判断——每条判断横跨三轴

**跨学派横轴触发规则**：
- 阶段2六维解剖完成后即触发——不依赖用户单独要求
- 若章句关键词（如「直」「命」「仁」）在孟荀中有明确对应论述，必须展开
- 若章句纯属礼制考据无哲学概念，可标注「[跨学派横轴不适用·本章无跨学派哲学概念]」

**典型产出**（6.17生直章案例）：
- 横轴：6.14行不由径 → 6.15难乎免 → 6.16文质彬彬 → 6.17幸而免
- 纵轴：「直」全书12+处仅6.17在本体层 → 「幸」全书3处均表概率/偶然
- 跨学派：孔「幸」=概率论 → 孟保留但边缘化 → 荀删除 → 佛置换为三世因果
- 三条收敛线：(1)「幸」的衰退史 (2)「君子固穷」四家答案 (3)6.14→6.17的后世分化

> 详见 `references/cross-school-horizontal-analysis.md`（6.17生直章完整跨学派横轴案例）。

**写作导向替代格式**：当阶段4直接服务公众号写作时，可用"写作锚点产出模板"替代证据分级综述格式——输出五个可操作锚点、说透五节点分配、开篇策略、注疏引用策略、冷知识锚点。详见 `references/writing-anchor-template.md`。

**证据分级**（贯穿三轴）：
1. **[实证]**：明确来自古籍原文，标注出处
2. **[推论]**：AI模拟观点，必须标注"基于X学派立场推测"
3. **[缺失]**：明确指出缺乏直接证据

**老丁因子（独立章节）**：
- 核心判断（一句话，须违背常见理解但可被文本与逻辑支持）
- 证据链（[实证]级证据，逐条对应）
- 论证路径（完整推理过程，每步可追溯）
- 潜在反例（预判质疑并给出文本回应）
- 与主流解释的分歧点（与朱熹/刘宝楠/钱穆等的差异）
- 定位说明（证据不足时标注[待挖掘]，不强行生成）

**老丁因子子类型：语法结构因子**

当注疏家对一个章句达成共识而该共识可能来自时代错位时，启用语法结构因子发现法：

**触发条件**（满足任一）：
- 某词在《论语》全书中仅出现一次（如「儒」全书1见）
- 某句式在全书中仅出现一次（如「女为X儒」祈使结构）
- 注疏家集体将祈使/规定句读成了描述/评价句

**发现步骤**：
1. **穷举全书同类用法**：扫描该关键词/句式在《论语》中的所有出现，统计语法结构（陈述句 vs 祈使句、系词 vs 及物动词）
2. **定位本章差异**：本章的语法模式是否不同于其他所有出现？如果是——这是一个文本级异常
3. **注疏时代错位检验**：注疏家是否将本章的语法读成了全书中其他出现的模式？如果是——他们做了「语法归一化」，原因是读《论语》时该概念已定型
4. **因子提炼**：将语法差异提炼为核心判断——「本章是全书唯一一次孔子不是在描述已有之物，而是在为一个尚未定型的东西预置方向」
5. **动词性验证**：检查核心动词（如「为」）在句中是系词还是及物动词——这个判断直接决定句子的性质是「成为X」还是「做成X」

**典型案例**：6.11为儒章。「君子喻于义」「小人长戚戚」等106次均为陈述句（描述已有之物），唯6.11「女为君子儒」为祈使句（规定未定型的方向）。「为」是及物动词「做成」而非系词「成为」。汉宋注疏家集体读成描述语——因为「儒」在他们时代已定型为学派专名，看不见它还处于被定义的瞬间。核心因子：「孔子说的不是描述，是立法。」

**与内容型因子的区别**：语法因子不依赖语义争论（「君子儒是什么意思」），而是依赖文本结构特征（「这句话的语法和其他106次都不一样」）。语法证据是[实证]级——可逐章穷举验证。

### 阶段 5：多格式生成

支持格式：Markdown（默认）/ PDF / Word

**9章输出结构**（启用什么输出什么）：

1. 原子化扫描结果
2. 政治史还原（如启用）
3. 注疏六维解剖（如启用）
4. 异常检测报告（如启用）
5. 变量替换实验（如启用）
6. 圆桌会议纪要（如需）
7. 证据分级综述

参考文献附于9章之后。

### 阶段 6：归档（可选）

将输出文档保存到笔记系统。建议使用笔记工具（如 Get笔记、Notion 等）保存到对应知识库。

标签规则：`论语研究`（必加）+ 文档类型标签 + 学派标签（最多5个）

### 用户框架注入协议（条件触发）

当用户在写作递进流程中（哲学转译后、提纲前，或任一步骤）提出自发的新解释框架并明确要求分析时，**不直接跳过——执行结构化检验后，再回到写作流程的断点**。

**触发信号**：用户提出一个与阶段4"老丁因子"不同的自发框架，并明确要求"分析是否自洽""与注家比较"。

**五步检验流程**：

1. **自洽性检验**：该框架内部逻辑是否一致？与原文用词（动词选择、语气词、赘词等）是否存在张力？如果有张力，指出解决方案或保留为「未解决张力」
2. **注疏逐家比较**：用阶段2的完整注疏清单，逐家判断——支持、冲突、相安无事（互不矛盾但路径不同）。用表格输出，三个分类列清楚
3. **独特锋芒识别**：该框架中最锐利的一个判断是什么？是否有一个注疏传统未说破的洞察？如果该框架的锋芒恰是注疏传统集体回避的方向——重点标出
4. **Get笔记发芽笔记交叉核验**：搜索 Get笔记中该章的发芽笔记（`{篇章名} 发芽` 或 `{章节号} {关键词}`），寻找共鸣、补充、或反例。发芽笔记中与该框架共振的金句直接引用
5. **整合建议**：指出该框架在文章提纲中最适合的落点（哪个段落/论证段），以及是否需要微调以避免与原文用词的张力

**输出格式**：表格（注疏比较）+ 文本分析（自洽性/锋芒/整合）。完成后暂停等用户确认，确认后回到写作递进流程的断点继续。如果用户要求将框架整合进提纲，修改提纲后再确认。

**与 classical-content-writer 的「用户概念重构处理规则」的关系**：anlects-review 的框架注入协议是**分析层**——检验自洽性和注疏定位；classical-content-writer 的重构规则是**写作层**——决定了「要不要回哲学转译重建」。两者先后执行：先分析，用户确认后，再决定写作层如何吸收。

### 文风铁律

- 简单直白，短句为主，可以"而且""但是"开头
- 删掉一切废话，禁用AI套话和营销话术
- 禁用开头套路（"说实话""咱们今天聊聊"）
- 禁用结语升华（"在这个时代""值得深思"）

### 比喻构建铁律

为古典概念构建现代比喻时，比喻必须匹配原文的结构关系，不可偷换概念的质地：

- **「有质无文」型比喻**：必须凸显「内在真诚 + 外在表达缺失」，而非「冒失/粗鲁/不懂礼貌」。检测标准：对照原文「敬而不中礼谓之野」——「敬」在前、「不中礼」在后。比喻必须保留「敬」这一层。❌ 错误：「赴宴坐主位、敬酒顺序搞乱」（质→冒失）。✅ 正确：「挖草药探病不敲门——草药是真的，心意是真的，只是不知道探病的形式」（质→真诚但无形式）
- **「文胜质则史」型比喻**：必须凸显「形式过剩 + 真诚缺失」，而非「虚伪/欺骗」
- **通用检测**：完成比喻后，用原文关键训诂词代入比喻——包子质→「质，实也」=草药是真的；包子文→「文，华也」=没包装没说客套话。能对上的比喻才合格

### 多义词澄清铁律

当文章分析的关键词在《论语》中有多重含义时（如「史」既可指策祝又可指史官），必须在辨析各家说法之后，追加一句明确的站位：「本章的X取的是Y这一路」。目的：不让读者在多种可能性之间悬置。6.16文质章教训——文章详细辨析了「史有二」，但没有明确说「本章取策祝义」，读者读完仍不知道孔子批的到底是什么。

### 开头/结语要求

- **开头**：历史场景入戏或意外引文，让读者第一行就觉得"不一样"
- **结语**：2-3段内收尾，用具体形象或场景收，说七八分留两三分

### 引用与节奏

- 引完古文立刻用大白话翻译，一行都别省
- 连续3段以上考据时加"换挡缓冲"
- 不要小标题，段落自然衔接

## 特殊分析框架：修身 vs 不违

**触发条件**：原文使用「违」「至」等空间/方向性动词而非「修」「进」「成」等功夫论动词时，启用此框架。

**核心命题**：本章可能不是讲「如何修身以达仁」，而是讲「如何不违仁」——区别在于前者假设仁在外面需要抵达，后者假设仁已在、问题是不离开。检验标准：「违」「至」暗示空间关系（居留/访问），而非修炼进度。

**分析步骤**：
1. 统计原文动词类型：功夫论动词（修/进/成/克/复）vs 空间动词（违/至/居/去/入/出）
2. 若空间动词占主导 → 推进「不违」框架：仁心人人本有（或仁已在外但可至），区别在续航力而非含量
3. 对照注疏：哪些注家做了功夫论转换（把空间动词解释为修炼方法）？哪些保留了结构描述？
4. 证据锚点：「而已矣」的开放性结尾、「其心」的内部声明、「三月」的模糊时间——三重沉默共同指向「判断不闭合」

**与注疏的典型张力**：
- 朱熹：功夫论转译最强——「不违=无私欲」，把空间描述变成操作方法
- 钱穆：部分保留空间隐喻（薪火喻），但仍有「可燃度提升」的操作暗示
- 康熙：完全量化——空间差异变成等级阶梯
- 何晏/皇侃：较接近原结构——「移时不变」「引汲」保留空间/时间框架

**老丁因子触发**：当发现「所有注疏家都在填空（给出操作指南）而原文没有任何操作指南」时→老丁因子等级提升。核心判断模板：「孔子这一章不是在教，是在判断。判断不需要操作指南。」

| 下游Skill | 触发方式 | 交接内容 |
|-----------|---------|---------|
| classical-content-writer | 用户要求完整写作协议 | 9章分析结果（上下文中已有） |
| cultural-comparator | 用户要求中西文化比较 | 分析中的核心概念（key_concepts） |

## 质量自检清单

**原则零自检：**
- [ ] 是否根据文本特征正确选择了方法论工具？
- [ ] 已启用的工具是否全部执行到底？
- [ ] 执行顺序是否遵循固定顺序？
- [ ] **年代校验是否完成了外部生平检索？涉及人物生平时，是否搜索了百度百科等外部来源补全注疏docx中缺失的生卒、任职、家族信息？**
- [ ] **同行对比验证是否完成？当某人拒绝出仕/辞官时，是否列出了同时接受类似任命的人，并区分了职位类型？**
- [ ] **物理动作动词是否被检查？六维解剖时是否逐家检查注疏对原文中动作动词（执、问、自等）的处理？注疏集体忽略某动作动词时是否标注？**
- [ ] 所有推论是否标注了[实证]/[推论]/[缺失]？
- [ ] 术语是否全程一致？
- [ ] 老丁因子是否包含6个子结构？
- [ ] 冷知识命题是否有触发点支撑？

**输出风格自检：**
- [ ] 是否避免"这段话说的是……""它告诉我们……"等顺滑解释句式？
- [ ] 输出是否呈现为可辨识的结构单元（命题/前提/分歧/路径/证据等级）？
- [ ] 是否构建了至少两种竞争性解释模型（而非只给"标准答案"）？
- [ ] 是否存在未标注的现代价值观投射？

**提示词库自检：**
- [ ] 每次对话是否只用一个 Prompt（不用多个合并）？
- [ ] 每个 Prompt 的输出是否用于下一 Prompt 的输入（流水线）？
- [ ] Prompt 2 是否构建了至少三种不可合并的解释模型？
- [ ] Prompt 4 是否指出了"最致命缺陷"？
- [ ] Prompt 7 是否只输出了结构骨架（而非全文）？

**工作流自检：**
- [ ] 每个阶段是否暂停等用户确认？
- [ ] 确认后是否自动保存（.md文件 + Get笔记）并直接推进，未多问「是否继续」？
- [ ] **阶段2多段确认时**：每子批次（如六维解剖1-5号、6-11号等）经用户确认「继续推」后，是否立即保存该子批次的 .md + Get笔记？是否在全部18家完成后一次性补存？（正确：每个子批次独立保存）
- [ ] 检查点A/B0/B是否都执行了？
- [ ] **阶段2六维解剖前，是否先输出「材料遍历清单」（列出所有注疏立场），并经用户确认？**
- [ ] **阶段间保存是否写入完整内容？`.md` 文件和 Get笔记 中不可出现"完整内容见上轮对话输出"等指向对话的占位符——每个文件和每条笔记必须独立可读。Get笔记推送是否使用了完整正文而非摘要？六维解剖等长内容文件大小是否与对话输出体量匹配（通常 6,000-10,000 字符）？**
- [ ] **结构化研究大纲法**：若触发了前置研究（无 docx / 缺材料 / 跨领域搜索），大纲是否经用户确认后才开始搜索？每个 item 是否串行搜索并标注了 [实证]/[推论]/[缺失] 证据分级？
- [ ] 圆桌会议是否包含至少两组对立立场？代表学者数量是否合理（≥4位，不强制6位）？
- [ ] 苏格拉底是否提出了至少3个致命反问？
- [ ] 幻觉控制：所有引用是否有明确出处？
